2.2.1.0

We are updating the docs...finally!
We are migrating our documentation and adding major updates. Please bear with us during this transtion.

2.2.1.0

New in 2.2.1.0

  • File names colorized in Build Data View.
  • Added command to de-duplicate file names in Build Data View.
  • Property Area can now be minimized further.
  • Resolution and PX (fraction for 1 pixel) constants added to Expressions and Math nodes.
  • FIX: Improved thread-safety for a rare condition that could cause a crash.
  • FIX: Draw window toolbar overlapped with terrain.
  • FIX: Draw window could malfunction if resized too widely.
  • FIX: Draw kept drawing when mouse would leave the window.
  • FIX: Draw "Lite" mode would still re-render node while drawing.
  • FIX: Portals connected to masks could revert to connections.
  • FIX: First frame of Turntable Animation could be malformed.
  • FIX: Added warning when trying to execute on AVX2 non-compliant CPU.
  • FIX: Mixer color randomization and values improved.
  • FIX: Incorrect behavior in gizmo for Perlin, Voronoi, Snow, Radial Gradient nodes.
  • FIX: 2D viewport would not show Locked Preview when opening.
  • FIX: 2D viewport would scroll when zoomed in.
  • FIX: 2D viewport maximum zoom set to 10X.
  • Several internal fixes.

Houdini Quality-of-Life Features

  • Added commands to File and Export node to automatically created variables.
  • Export node variable naming improved:
    • If Export does not have an explicit name, the variable will be called "OutIncomingNode" (ie, "OutSwirl").
    • If Export node has a custom name, variable will get that same name.
    • If Export node is renamed at any point, user is asked if variable should be renamed too.
  • In / Out variables get color coding in the Var list.
  • Notification when orphan variables are found.
  • Rename variable when node is renamed.
  • Warn when using Mark for Export instead of Export nodes.
  • Allow renaming of In / Out variables without entering Edit Mode.

Breaking Changes

The following nodes may not be fully backward compatible with Gaea 2.1 or earlier builds.

  • Trees
  • Cellular3D
  • Debris
  • ThermalShaper (minor variance in results)

It is highly recommended that if you migrate an active project from Gaea 2.1 to 2.2, that you make a backup first and ensure all your nodes are behaving properly.

Gaea will attempt to create a Recovery copy in the Autosave folder for disaster recovery, but you should still keep a manual backup copy just in case.
